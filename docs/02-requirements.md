# 要件定義書

対象は SKYTRACE Web / PWA v0.2.0。実装の受入と、本番公開先での受入を分ける。

## 1. 範囲と利用者

PC / スマートフォンの閲覧者が観測数・位置・機体詳細を確認する。認証なしの読み取り用途を中心とし、管理者が設定・公開・データ利用枠・DB を管理する。ストアへの配布、ユーザー登録、機体の過去航跡、空港ルート、広告・決済は今回の範囲外。

## 2. 機能要件

| ID | 要件 | 受入条件 |
| --- | --- | --- |
| FR-01 | 観測数と統計 | 飛行中、全有効観測、位置あり、登録国数、平均値を返す。集計を検索や地図サンプルで減らさない |
| FR-02 | 世界地図 | 有効で新しい位置だけを表示。範囲取得とサンプリング、地図タイル障害時の簡易背景と帰属表示 |
| FR-03 | 検索・並び替え・ページ | callsign / ICAO24 / 登録国。検索 80 文字以内、callsign 昇順・高度 / 速度降順、欠損後方。一覧の標準 8 件 |
| FR-04 | 詳細 | 選んだ一機だけ取得。識別子、登録国、位置、測定値、通信時刻。不存在 404、不正識別子 400 |
| FR-05 | 単位と意味 | 高度 m、画面の速度 km/h、垂直速度 m/s、地上航跡 °。NULL を 0 として表示しない。登録国を飛行中の国と呼ばない |
| FR-06 | 状態と鮮度 | live / stale / unavailable / demo を区別。観測 120 秒超を古い状態にする。未取得の件数は不明表示。通信断を現在の実測と誤認させない |
| FR-07 | 取得間隔と制限 | 同時要求を一回の外部取得で共用。匿名標準 900 秒 / OAuth 120 秒、429 と失敗の期限を守り、再起動後も維持 |
| FR-08 | 明示的なデモ | ライブを初期表示。デモは明示選択または `?mode=demo`。DB・履歴・応答のモードを分離し、失敗時の自動切替なし |
| FR-09 | 保存と履歴 | 最新機体と機数履歴をトランザクション保存。24 時間 / 最大 1,440 点、API 直近 360 点。SQLite v1 の既存データを v2 に移行 |
| FR-10 | API と導入 | Node.js 24.5+、lockfile、DB 自動初期化、型チェック / ビルド。既存 `.git`・`.env`・DB と独自ファイルを保持する導入手順 |
| FR-11 | 少量の通信 | 新画面は summary / flights / map / detail を利用。一覧 API 最大 50 件、地図最大 1,000 件、標準 UI 200 / 600。旧全件 API は互換用 |
| FR-12 | PWA | manifest / アイコン / Service Worker、HTTPS でインストール可能。画面だけをキャッシュし、API と外部タイルは保存しない |
| FR-13 | 公開基盤 | ビルド済み Node.js サーバー、非 root の API コンテナー、DB 永続領域、Caddy HTTPS 例。起動 / 停止 / 健全性確認の手順 |
| FR-14 | 継続更新 | 本番はバックグラウンド更新。閲覧者ゼロでも利用枠と保存期限を守り、停止時に更新処理と DB を安全に閉じる |
| FR-15 | GitHub 管理 | 要件・設計・CI・依存更新・Issue / PR・セキュリティの文書をソースと同じ変更で管理 |

## 3. 非機能要件

| ID | 要件 | 実装の基準と公開受入 |
| --- | --- | --- |
| NF-01 | 性能 | 地図を遅延読み込み、Canvas 描画。初期 JS gzip ≤120 KiB、全 JS ≤300 KiB、全 CSS ≤40 KiB をビルドで確認。実端末の応答時間と同時閲覧数は別に測定 |
| NF-02 | アクセシビリティ | キーボード、見えるフォーカス、入力ラベル、ステータス案内、文字のコントラスト、動きの軽減。地図の情報を一覧 / 詳細でも確認。WCAG 2.2 AA を目標とし、自動検査だけで適合認証と呼ばない |
| NF-03 | レスポンシブ | 320 px 以上の幅で主要操作に到達し、横はみ出しを避ける。スマートフォンと文字拡大は公開前に実端末でも確認 |
| NF-04 | 安全な API | 読み取り専用、クエリ検証、SQL パラメーター、HTTPS、Helmet / CSP、既定 180 回 / 分 / IP の制限。秘密を応答やブラウザーへ送らない |
| NF-05 | プロキシ | 信頼する段数を明示し、偽の `X-Forwarded-For` で制限を回避させない。Compose の Caddy 構成は API のポートを外部公開しない |
| NF-06 | データ保護 | `.env` / DB を Git 対象外とし、WAL を考慮した停止後バックアップと復元。実データと合成データを混同しない |
| NF-07 | 保守 | lockfile、型、必要なテスト、CI、Dependabot、関連資料。SQLite v2 より新しい DB を古いコードで誤操作しない |
| NF-08 | 観測可能性 | health は API / DB の確認、取得状態は別に確認。公開先の監視、保存容量、ログ保持、通知先を公開時に決める |
| NF-09 | 正確な案内 | データ利用枠、古い状態、公開先未定、実 OAuth 未検証を明記。常時 1 秒更新、全世界の正確な機数、本番公開済みと称しない |

## 4. データ品質

OpenSky の `on_ground=false`、観測時刻に対し原則 120 秒以内の最終通信を対象にする。未来の通信は 30 秒の許容を設け、それを超える不正値は除外。同じ ICAO24 は最新通信を残す。位置は通信とは別に鮮度と範囲を検証する。高度は幾何高度優先、速度や位置が欠損すれば NULL とする。

正常な空の観測は 0 件として扱う。不正な応答や通信失敗を 0 件として成功扱いしない。保存済みより古い観測で最新状態を上書きしない。

## 5. 公開前に必要な条件

公開先 / ドメイン / DNS / TLS、運営者の設定、必要なデータ利用条件、OAuth が必要なら正式クライアント、IP 単位の利用枠、実スマートフォンの PWA、バックアップ復旧、同時アクセスと長期稼働の受入を確認する。予算・規模・SLA は未決定のため保証値を作らない。[公開前チェック](deployment-checklist.md) を受入表として使う。
