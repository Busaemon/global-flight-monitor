# 企画書：SKYTRACE / Global Flight Monitor

## 1. この企画の目的

世界で観測されている飛行中の航空機を、機数・地図・機体詳細から確認できる Web アプリを制作する。
利用者が「現在どれくらいの航空機が観測されているか」を把握し、気になった機体の位置・高度・速度を調べられる状態を目指す。

この文書は現在の初版実装を基準に、企画の背景、提供価値、対象範囲、制約、今後の判断事項を整理したものである。
企画書に将来案が記載されていても、現在のアプリにその機能が実装済みであることは意味しない。

## 2. ユーザーから確認できている要望

| 項目 | 要望 |
| --- | --- |
| 主な目的 | いま世界で飛んでいる飛行機の機数を確認したい |
| 詳細確認 | 航空機ごとの情報を確認したい |
| 制作範囲 | データベース、バックエンド、フロントエンドを制作する |
| 開発環境 | VS Code、PowerShell、Node.js、npm、Git、GitHub |
| フロントエンド | React、TypeScript、Vite を利用する |
| 配置方法 | 作成済みの `global-flight-monitor` フォルダーへファイルを追加できる形にする |
| ドキュメント | 要件定義、企画書などの詳細を GitHub に追加できる形で用意する |

予算、公開日、同時利用者数、有料サービスの契約、運営体制は指定されていない。
本書では担当者名、組織名、契約済みサービス、確定期限を追加していない。

## 3. 初版で採用した実装上の判断

以下は要望を具体化するための初版の設計判断であり、ユーザーが個別に指定した条件ではない。

| 判断 | 採用理由 |
| --- | --- |
| OpenSky Network の状態ベクトルを利用 | 公開 API から位置・高度・速度・識別子を取得できる |
| SQLite を利用 | 別の DB サーバーを用意せず、Node.js 上で保存・再起動を確認できる |
| Node.js / Express の API を配置 | 認証情報と取得制限をサーバー側に集約できる |
| 地図と一覧を同じ画面に配置 | 全体の把握から機体詳細の確認へ進みやすい |
| 日本語を主な画面言語にする | 現在のユーザーの利用・開発に合わせる |
| デモを独立したモードとして配置 | API が利用できなくても操作確認を進められる |
| 観測数の短期履歴を保存 | 時間経過による変化を表示できる |
| アカウントを初版に設けない | 観測・検索・詳細確認に必要な部分を先に完成させる |

商品名 `SKYTRACE` は画面に採用した初版の名称である。

## 4. 解決する問題と利用価値

航空機の位置情報は、そのままでは件数・鮮度・欠損の意味を読み取りにくい。
地図に表示できる機体だけを数えると、位置情報がない観測機体を見落とす。
また、API の更新間隔が長いと、保存された情報を「現在の確実な位置」と誤解する可能性がある。

本アプリは機数と地図の表示件数を分け、観測時刻、取得時刻、情報源、状態を画面に示す。
航空機を選択すると、現在の保存済み観測から詳細を確認できる。
通信できないときは最後の観測を区別して表示し、保存済み観測がないときは機数を不明として扱う。

| 利用場面 | 初版で得られる価値 |
| --- | --- |
| 世界の航空交通に関心がある | 観測された飛行中機数と地理的な広がりを確認できる |
| 特定の識別子を調べたい | callsign・ICAO24・登録国で検索できる |
| 一機の動きを知りたい | 高度・対地速度・地上航跡・垂直速度を確認できる |
| 学習・個人開発に使いたい | React、API、SQLite の構成を一つのプロジェクトで理解できる |
| 外部 API が使えない状態で確認したい | 明示的にデモを選び、地図・検索・詳細を試せる |

これらは企画上の想定利用場面であり、利用者調査を実施した結果ではない。

## 5. 提供する中心機能

1. 観測中の飛行中航空機数を表示する。
2. 有効な位置情報を持つ航空機を世界地図に表示する。
3. callsign、ICAO24、登録国を条件に検索する。
4. 一覧または地図から機体を選び、観測値の詳細を表示する。
5. 飛行中機数の保存履歴をグラフで表示する。
6. ライブ、最終取得データ、取得不可、デモの状態を区別する。
7. API の利用枠を守る取得間隔と保存済みデータを共用する。
8. 既存フォルダーに必要なソースを置き、PowerShell から起動できる形にする。

集計・検索の対象は保持している全飛行中機体である。
地図は描画負荷を抑えるため最大 1,200 機を間引いて表示する。
一覧は 1 ページ 8 件で表示するため、地図の間引きで検索対象が減ることはない。

## 6. 「世界で飛んでいる機数」の定義

初版の機数は、OpenSky が受信した状態ベクトルのうち、飛行中かつ新しい通信情報を持つ機体の件数である。
全世界のすべての航空機を網羅した正確な総数ではない。
受信局の範囲、情報発信の状態、API の制約により、実際に飛んでいても含まれない機体がある。

同じ ICAO24 が複数届いた場合は、最終受信時刻が新しいレコードを採用する。
OpenSky の観測時刻に対して最終受信が 120 秒より古い機体は除く。
地図用の位置情報も 120 秒以内で、緯度・経度が有効なものに限定する。
位置が欠ける機体でも飛行中の条件を満たせば、機数と一覧に含む。

`origin_country` は機体の登録国であり、現在飛んでいる国や出発国ではない。
callsign は通信上の識別情報であり、旅客向けの便名との確実な対応を保証しない。
高度は幾何高度を優先し、取得できないときは気圧高度を使う。
速度は対地速度であり、対気速度ではない。

## 7. 更新方式とデータの鮮度

| 項目 | 初版の標準値・動作 |
| --- | --- |
| 匿名 OpenSky 取得 | 900 秒ごと（15 分） |
| OAuth 設定時の取得 | 120 秒ごと（2 分） |
| ブラウザーの状態確認 | 標準設定では 30 秒ごと |
| デモの生成・状態確認 | 10 秒ごと |
| ライブ観測の期限 | 観測から 120 秒を超えると最終取得データとして表示 |
| 再取得ボタン | ローカル API に問い合わせ、上流の取得期限は守る |
| 取得実行の契機 | API にアクセスされ、次回取得期限に達しているとき |

「リアルタイム」は、新しい観測を定期的に取得して表示する意味で利用する。
初版は一秒ごとの世界全体の位置更新を提供しない。
匿名利用では 15 分の取得間隔と 120 秒の鮮度期限があるため、多くの時間帯で最終取得データの表示になる。
取得間隔を短縮する場合は、利用資格・クレジット・提供条件を先に確認する。

閲覧者が増えても、同じ Node.js プロセス内では上流への同時取得をまとめる。
画面を閉じて API へのアクセスがない期間の観測履歴は、自動的に連続収集されない。

## 8. 初版の範囲と今後の候補

| 現在提供するもの | 将来の検討候補 |
| --- | --- |
| 観測数・世界地図・検索・機体詳細 | ユーザー登録、ログイン、お気に入り |
| 短期の観測数履歴 | 長期履歴、機体ごとの軌跡再生 |
| callsign・ICAO24・登録国 | 機種、機体登録番号、航空会社の補完 |
| OpenSky のライブ観測 | 別の情報源、空港・路線・到着予定情報 |
| ローカル開発・単一サーバー実行 | 公開用の運用、複数サーバー、監視 |
| 合成データによるデモ | 利用者ごとの設定・通知 |

出発空港、到着空港、遅延、運賃、旅客数、予約操作は初版に含まれない。

## 9. 開発・運用の前提

Node.js は `24.5.0` 以上を必要とし、npm はロックファイルに合わせて依存関係を導入する。
SQLite は標準で `data/flights.sqlite` に作成され、GitHub へ保存しない。
OAuth の秘密値は `.env` または実行環境の設定で扱い、画面・GitHub・配布物に含めない。
地図タイルには OpenStreetMap / CARTO の帰属表示を残す。
タイルが利用できない場合は、同梱の Natural Earth 陸地データを簡易背景として利用する。

公開用ドメイン、TLS 終端、バックアップ、稼働監視、利用者数の目標は今後の設計事項である。
これらを準備済みとみなした公開計画や費用計画は設定していない。

## 10. 完成の判断と関連資料

初版の完成は、既存フォルダーへの配置後に依存関係の導入、DB 初期化、起動、機能確認、テスト、ビルドを実行できることで判断する。
`npm run setup` は依存関係の導入、DB 初期化、型確認、ビルドをまとめて行う。
その後、`npm run dev` で開発用の API と画面を起動する。
ライブ取得は外部 API の利用可否に左右されるため、取得できない場合の表示と明示的なデモ操作も確認する。
性能・大量アクセス・本番運用の達成は、別途計測と運用準備を行った時点で判断する。
