# 企画書：SKYTRACE / Global Flight Monitor

## 1. 目的

世界で観測されている飛行中の航空機の機数、位置、高度・速度などの詳細を、PC とスマートフォンで確認できる Web / PWA を制作する。合成データによる操作確認に加え、実データを中心とする公開運用の基盤を整える。

機数は OpenSky Network の観測範囲の値であり、世界の全航空機の正確な総数ではない。航空管制、航行、安全判断に使用するためのシステムではない。

## 2. 確認済みのユーザー要望

| 項目 | 内容 |
| --- | --- |
| 中心機能 | 飛行中機数と機体詳細を確認する |
| 制作範囲 | DB、バックエンド、フロントエンド、企画 / 設計資料 |
| 開発環境 | VS Code、PowerShell、Node.js、npm、Git、GitHub、React、TypeScript、Vite |
| 配置 | 既存 `global-flight-monitor` フォルダーへ追加できる |
| スマートフォン | Web とホーム画面アプリ（PWA） |
| 品質 | 軽さ、セキュリティ、アクセシビリティ、見やすさ、GitHub の詳細 |
| 公開先・OAuth | 未定 / 未用意。実装と検証は先に進める |
| 作業対象 | このプロジェクトに関係するファイルのみ。必要なインターネット利用可 |

予算、公開日、同時利用者数、商用契約、運営担当者は未指定。期限や契約済みサービスを仮定しない。

## 3. 提供する価値

| 場面 | 提供する動作 |
| --- | --- |
| 世界の航空交通を知る | 全観測の飛行中機数、位置あり機数、登録国、履歴を確認 |
| 特定の機体を探す | コールサイン・ICAO24・登録国で検索し、一覧や地図から選択 |
| スマートフォンで見る | 画面幅に合わせる、一覧を少量取得、地図を Canvas 描画 |
| ホーム画面から使う | HTTPS 公開後に PWA として追加。オフライン状態を明示 |
| 外部 API が利用できない | 最終観測の鮮度または取得不可を表示。操作確認は明示的なデモで行う |
| 継続して開発する | 同じ GitHub 履歴にソース・要件・テスト・運用を保存 |

これは企画上の利用場面で、利用者調査を実施した結果ではない。

## 4. 採用した方針

React / TypeScript / Vite、Node.js / Express、Node.js 標準 SQLite を利用する。API 認証と利用枠の管理をサーバーに集約する。PWA は同一オリジンの画面の基本ファイルを保存し、観測 API と外部タイルは保存しない。

全機体 JSON と多数の DOM マーカーをスマートフォンへ送る構成を改め、集計・一覧・地図・詳細の API を分ける。地図のコードを遅延読み込みし、描画数を抑える。DB は単一サーバーの永続領域に置き、HTTPS リバースプロキシの公開例を用意する。

ライブを初期表示にし、モードを明示する。提供元の実データを欠損や取得不可から推測して作らない。ログイン・課金・プッシュ通知・ストア向けネイティブアプリは今回の範囲に含めない。

## 5. データの制約

| 制約 | 対応 |
| --- | --- |
| 受信範囲、送信状況による欠落 | 観測値と説明を表示し、全世界の正確な総数と記載しない |
| 匿名 API の日次枠 | 標準 900 秒、共有キャッシュ、429 の待機と再起動後の維持 |
| OAuth が未用意 | 匿名で動作可能。短い間隔は正式クライアントと利用枠確認後 |
| 観測と取得の時刻が異なる | 両方を保持し、観測から 120 秒超は古い状態と表示 |
| 位置だけ欠損する | 集計・一覧に残し、地図から除く |
| ルート・機種・旅客数がない | 架空の値で補わない |
| 地図タイルは外部通信 | 帰属表示を維持。失敗時は同梱の簡易陸地を使用 |

OpenSky、地図、依存コードの利用条件は別に確認する。公開や商用利用が承認済みであるとは仮定しない。

## 6. 完了の判断

今回の実装完了は、ページ / 範囲取得、PWA、セキュリティ、読みやすいレスポンシブ画面、テストと資料が同じ変更として用意されること。公開完了はさらに、実ドメインの HTTPS、正式な設定、実端末、利用枠、バックアップ / 復旧、負荷と監視を確認すること。公開先が未定の現段階で公開完了とは表現しない。
